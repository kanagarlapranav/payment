1. Hardcoded Bot Token in Source Files & Git History
Critical Severity

Friend's Observation: Real TELEGRAM_BOT_TOKEN is hardcoded in check_messages.py (line 6) and setup_env.py (line 6). Because these are standard .py files, .gitignore did not exclude them, leaving the token exposed in Git history.

Code Verification:

  • check_messages.py:6: BOT_TOKEN = "8863268724:AAFcDfpdgTXas2E6OnNIQj9mRIwRzQ8WV94"
  • setup_env.py:6: BOT_TOKEN = "8863268724:AAFcDfpdgTXas2E6OnNIQj9mRIwRzQ8WV94"
  • Git Inspection: Both files were committed in commit affae64155db5ab9eddcce8afe31bf6379790193 and pushed to https://github.com/kanagarlapranav/payment.git.
Security Impact: Anyone who views the GitHub repository or commit log has full administrative access to your Telegram bot. They can read uploaded payment screenshots, intercept OCR data, and delete or falsify records.

Recommended Solution:

  1. Open Telegram → @BotFather → /mybots → select your bot → API Token → Revoke current token. This instantly invalidates the leaked credential.
  2. Update the new token in your Render Environment Variables and your local .env.
  3. Refactor both scripts to load the token from the environment: 
    import os
from dotenv import load_dotenv
load_dotenv()
BOT_TOKEN = os.getenv("TELEGRAM_BOT_TOKEN")
if not BOT_TOKEN:
    raise ValueError("TELEGRAM_BOT_TOKEN is not set in environment or .env")
2. Authorization & Access Control Gaps
High Severity

Friend's Observation: Check if user authorization actually protects sensitive financial data from strangers who find the bot username.

Code Verification:

  • The Good: All text commands (/balance, /history, /delete, etc.) and incoming photos check is_authorized(update) in bot/commands.py.
  • Vulnerability A (Callback Handler): In bot/handlers.py (line 171), handle_callback_query() processes button presses without calling is_authorized(update). Anyone with access to the chat or message can click confirm_tx, cancel_tx, or delete_confirm.
  • Vulnerability B (Group Chat Broadness): is_authorized() authorizes any update where chat_id == TELEGRAM_GROUP_ID. If the bot is ever placed in a group with multiple users, other group members can trigger destructive actions like /delete or /setbalance.

Recommended Solution:

  • Add if not await is_authorized(update): return at line 174 of bot/handlers.py.
  • Ensure critical admin commands (/setbalance, /delete) strictly verify user_id == TELEGRAM_USER_ID rather than permitting any user in the group chat.
3. Conflicting Deployment Architectures (Render vs Vercel / Netlify)
Medium Severity

Friend's Observation: Long-polling daemon (app.py + render.yaml + Procfile) is fundamentally incompatible with serverless functions (vercel.json + netlify.toml + api/index.py).

Code Verification: Confirmed. The repository contains two opposing architectures:

  • Daemon Architecture (Render): app.py runs a persistent polling loop (app.run_polling()), startup restore hooks, and background keep-alive threads.
  • Serverless Architecture (Vercel/Netlify): api/index.py runs stateless HTTP handlers. In serverless environments, SQLite files are ephemeral per-invocation, in-memory transaction states are lost, and 10s execution limits cause OCR timeouts.
  • The Webhook Trap: Running set_webhook.py registers a Telegram webhook, which immediately halts long-polling on Render!

Recommended Solution: Standardize exclusively on Render. Delete vercel.json, netlify.toml, api/index.py, and set_webhook.py to prevent accidental misconfiguration.

4. Tesseract OCR vs RapidOCR on Render Cloud
Low / Informational

Friend's Observation: requirements.txt installs pytesseract, but Render's native Python runtime lacks the OS-level binary (tesseract-ocr), leading to potential TesseractNotFoundError.

Code Verification:

  • Your codebase in ocr/engine.py is already smarter than your friend assumed. RapidOCR (ONNX Runtime) is the primary engine and executes without external OS binaries.
  • Tesseract is only invoked as a secondary fallback after checking shutil.which('tesseract') or os.path.exists(TESSERACT_CMD). On Render, both return False, so it gracefully skips Tesseract without throwing uncaught exceptions.
  • Housekeeping Note: tesseract_setup.exe (a 50 MB Windows executable) is sitting in your workspace root, and pytesseract is listed in requirements.txt unnecessarily.

Recommended Solution: Remove tesseract_setup.exe and consider removing pytesseract from production requirements.txt to speed up Render build times.

5. SQLite Database Persistence on Ephemeral Cloud Disks
Medium Severity

Friend's Observation: Render's free tier wipes local disk storage on redeploys and restarts. Confirm that cloud backups run after every write.

Code Verification:

  • You have implemented an automated backup engine in services/backup_service.py that dumps SQLite to JSON and sends it to Telegram, with automatic restore on startup in app.py.
  • Identified Gap: Backups are dispatched when new transactions are added or deleted, but NOT when running /setbalance <amount> in bot/commands.py:530. If Render restarts after you update the balance, your balance setting reverts to the previous backup state.

Recommended Solution: Add asyncio.create_task(backup_to_telegram(context.bot)) inside setbalance_command().

6. Self-Ping Keep-Alive vs External Uptime Monitoring
Low / Advisory

Friend's Observation: Self-pinging every 10 minutes from within the same Python process cannot revive a crashed or frozen container; an external monitor is cleaner.

Code Verification:

  • app.py:91-103 runs start_keep_alive() pinging RENDER_EXTERNAL_URL every 10 minutes.
  • Render Quota Consideration: Render Free Web Services grant 750 free instance hours per calendar month. Keeping a single service awake 24/7/365 burns 744 hours (99.2% of your monthly quota). If you have any other service running on the same free account, your instance will be suspended until the 1st of next month.

Recommended Solution: Set up a free external ping monitor on cron-job.org or UptimeRobot hitting your / endpoint. If you want to conserve Render free hours, set the ping schedule to active hours only.
